# System Patterns: L2 Medical Information System

> **Language Requirement:** All Memory Bank documentation must be written in English.
> New entries, updates, and modifications must be in English.

## Architecture

### Architectural Style
- **Monolithic architecture** with modular Django apps
- **Micro-frontends** via Vue.js components
- **Asynchronous processing** via Celery for long operations
- **REST API** for frontend-backend communication

### Layers
```
┌─────────────────────────────────────┐
│   Presentation Layer (Vue.js)       │
├─────────────────────────────────────┤
│   API Layer (Django REST Framework) │
├─────────────────────────────────────┤
│   Business Logic Layer (Views)      │
├─────────────────────────────────────┤
│   Data Access Layer (Models)        │
├─────────────────────────────────────┤
│   Database (PostgreSQL)             │
└─────────────────────────────────────┘
```

## Key Design Patterns

1. **MVT (Model-View-Template)** - Django's core pattern
2. **Repository Pattern** - SQL functions in `sql_func.py`, custom managers
3. **Service Layer** - Business logic in `utils.py`, `manager.py` modules
4. **Factory Pattern** - Complex object creation (referrals, documents, forms)
5. **Strategy Pattern** - Different processing based on type (lab/paraclinical, research types, integrations)
6. **Observer Pattern** - Django Signals for auto-logging, triggers, `slog` module
7. **Command Pattern** - Django management commands, Celery tasks, API endpoints

### Financial Domain
- `contracts/` - contracts
- `cash_registers/` - cash operations
- **CITO pricing:** `PriceCoast.coast_cito` on the same price row; `PriceCoast.resolve_coast(coast, coast_cito, is_cito)` returns CITO price when `is_cito` and `coast_cito > 0`, else base `coast`. Direction creation passes `is_cito` into `gen_napravleniya_by_issledovaniya` so `Issledovaniya.coast` is set correctly at creation.
- **Hospital research synonym:** `TitleResearchHospital` stores a per-hospital service title. Constructor `/ui/construct/price` shows an editable column after the research name (save with the price row). Excel `100.01` reads/writes column `Синоним`. Both save only for **Заказчик** prices that have a hospital; empty values are skipped. On `/ui/request-creation`, if the current user's hospital has a synonym, it replaces the service title in the assignment picker, the request list, and result print (`result_print` / schema docx). `Hospitals.only_services_with_hospital_synonym` (default off) limits that picker to services that have a synonym and rejects `requests/create` without one. `/ui/requests-fill` cards and the protocol title (`directions/paraclinic_form` when `is_request`) use the synonym of the request hospital (`Napravleniya.hospital`), including when the describing doctor belongs to another organization.
- **Gardening electricity:** `GardeningElectricityMeter` is the single plot-level meter list with optional `date_start` / `date_end`. Each meter also stores subscriber address, subscriber name, device type, and serial number — edited in the meter modal from both the owner form and electricity readings. Owner modal and electricity readings both read/write that model; meters are not deleted — they are closed by end date. `_ensure_meters` creates «Счётчик 1» if none exist. `GardeningElectricityMeterReading` belongs to a meter. The year table and PDF only include months that overlap the meter period. Charge is per active meter. **Списано** is also per meter: the plot write-off (`min(available, total charge)`) is allocated across meters in display order, each row up to its own charge. **Приход / Долг / Остаток** stay plot-level and are shown on the first active meter of that month (and on the month total). Missing tariff is red `0.00`. Current reading cannot be less than previous (equal is allowed); create/update reading APIs and both UIs (plot table, month list, previous-reading modal) enforce this. UI: `/ui/gardening` object panel, plus to add a meter, pencil modal for dates. Owner table is full width (10px right inset) and includes email (`OwnersRealEstate.email`) and plot area (`RealEstate.area`). Plot area and email are edited in the owner add/edit modal.
- **Gardening plot contributions:** Object panel shows a **Взносы** table on the same row as **Приход (Банк)** (each 50%), below the owner. Rows are year payment types except electricity and `not_control`. Columns: title, tariff (year overlapping rate), coefficient (`1` for absolute / neither, plot `RealEstate.area` for `is_by_area`), charged, written-off, debt, remainder. Money uses the electricity remainder rule (`available = previous remainder + bank receipts`, written-off = min(available, charge), debt = shortfall, remainder ≥ 0). Yearly period charges the overlapping rate once; monthly period sums 12 monthly rates. `is_by_area` charges **rate × area**. Missing tariff, area (for by-area), or charge is red `0.00`. Plot area (m²) is edited in the owner add/edit modal and saved on `RealEstate`. API: `gardening/get-plot-contributions`. The table refreshes when bank receipts or owner/area change. PDF `115.01` prints this table after bank receipts and before electricity.
- **Gardening accounting (Все):** In Учёт mode with «Все» selected, the header shows year payment types. If the selected type is electricity (`is_use_kilowatt` or title contains «электроэнергия»), a January–December month strip appears below the types, plus **Долги** after December. Clicking a month opens `GardeningElectricityMonthList`: one row per active meter across plots (plot, meter, previous/current readings with date headers, consumption, tariff, charge, written-off, plot totals: consumption, written-off, debt, remainder, receipt). Plot-total columns (`* общ`) show values only on the first visible row of each plot after filters/sort. Column sort; filters for debt and missing current reading. Inline reading edit uses the same create/update reading APIs as the plot electricity table. API: `gardening/get-electricity-month-rows`. **Долги** opens `GardeningDebtsList`: plots whose **cumulative** unpaid electricity debt through the as-of month is > 0 (today’s month of the selected year, or December if the year is past). Charge / written-off / debt are sums of monthly values from the start of the calculation through that month; remainder is the as-of snapshot. July’s unpaid charge still appears in September if it was not covered. API: `gardening/get-payment-type-debts`. Other payment types (except `not_control`) open `GardeningAccountingSummary` in table mode: one row per plot with the same fields and formulas as plot **Взносы** (`_contribution_row`): tariff, coefficient, charge, written-off, debt, remainder. Missing tariff/area/charge is red `0.00`. Column sort and a debt filter. «Итого» still lists types with bank receipt totals. API: `gardening/get-accounting-summary`. The **Участок** column in both all-plots tables is a link `/ui/gardening?id=<plot>&year=<year>` (`target=_blank`); the page reads these query params on load and opens that plot card in Учёт. **PDF** and **Excel** on each Все view print the current table (`forms` type `115.02` / `forms.xlsx.forms115.form_02`): same columns, filters, and sort as on screen. Helper `_all_plots_export` builds the payload. In **Настройка**, **Бэкап SQL** (next to База) downloads a gzipped full `pg_dump` of the PostgreSQL database (`gardening/backup-sql`).

### Document Flow
- `forms/` - document templates
- `construct/` - form constructor
- `document_management/` - document management

Layout templates are no longer created under `/ui/construct/descriptive` (**Шаблоны**). **Формы** stay on descriptive. Type editor **Создатели** assigns who may create that type: addressee-style picker (constructor sets or specific employees; “add set” snapshots members). Stored as `TypeDocumentCreator` (`type_document` + `doctor`). Empty creators = no restriction. Case types APIs: `document-manager/cases/list` and `document-manager/cases/update`. **Планы** (`Plans`) are created on `/ui/construct/dou`: a plan holds **Показатели** (`Researches.is_indicator`) in `PlanIndicatorGroup` rows or on their own (`PlanIndicator.group` empty). APIs: `document-manager/plans/list`, `plans/details`, `plans/update`.
- **DOU document manager** (`/ui/document-manager`): `DOCUMENT_MANAGER_FOR_ALL` in `laboratory.settings` / `local_settings` (default `False`) is an on/off switch: when `True`, the menu button, page, and `ДОУ: просмотр документов` APIs ignore groups and are open to every authenticated user (`modules.document_manager_for_all` on the frontend). When `False`, access stays on group **ДОУ: просмотр документов**. `HIDE_DOCUMENT_MANAGER` (default `False`, override in `local_settings`) hides the **ДОУ** menu button and `/ui/document-manager` for everyone, including a direct URL (`modules.document_manager_enabled` is false). **ДОУ-2**, the constructor, and document APIs stay. Constructor, history, hide, and confirm-reset stay on their groups. A `Documents` row has `Issledovaniya.document`; field values are `ParaclinicResult` on that iss (same payload as `directions/paraclinic_result`, without direction-only side effects). Save stays on `document-manager/documents/save` because DOU users have group **ДОУ: просмотр документов**, not the doctor groups for `paraclinic_result`. Confirm writes `Issledovaniya.time_confirmation` and mirrors `Documents.time_confirm` / `who_confirm`. Confirm reset is limited to Django group **Сброс документов** (or superuser); details returns `canReset`. Hide is allowed for the document author until confirm, plus superuser and Django group **Скрытие документа**; details returns `canHide`. Hidden documents are listed/opened only for that group and superuser; the **Скрытые** checkbox is shown only then. **Мои дела** sits before it and lists non-hidden documents of cases the current user created or was granted access to. Opening a case from **Мои дела** or from **Избранные дела** shows only the case block and a **Документы** list. Each row is one line (topic, type, creation date, creator) plus a blue **Перейти** link that opens that document in a new tab via `?document=`. **+** / **−** beside the heading expand or collapse every row; the same control on a row shows or hides that document's electronic form. Other filters keep the document form and the case block without that list. The case heading is **Дело №** plus the case pk, with a star that toggles `UserFavoriteCase` for that case (`record-favorites/toggle` with `case: true`). Each document line starts with the document pk. A case has a comment and can be closed by its creator or a superadmin; closing stores the date and the user. Under the document buttons, a treeselect lists open cases the user can access and assigns the document to the chosen case. It stays off together with **Скрытые**, **Новые**, **Последние**, **Согласовать**, and **Подписать**. Actions write `slog.Log` with types 260000–260005 (`key` = document pk). History UI `/ui/document-history` (group **История документа**) matches `/ui/direction/history` (search by number, grouped event cards) and reads only those types via `document-manager/documents/history` — not `/ui/logs`. **Найти** looks up `Documents.pk` via `documents/find` (`Documents.find_by_id`); changing group reloads types only, not the document list. Field type 45 **Адресат** stores JSON `[{id, fio}]`; save syncs `DocumentReview.doctor_review` for the document. Addressee sets are `AddresseeGroup` / `AddresseeGroupMember`. Surrogate group **Все** is only for Django group **Все адресаты** or superuser (constructor may still search all employees). Constructor sets have empty `who_create`; personal sets from the document modal belong to the current doctor and are listed only for that user. Opening a confirmed document (`documents/details`) stamps `time_review` on that user's pending `DocumentReview` row without reloading `Issledovaniya`. Repeated opens update `DocumentRecent` without trimming the 200-row cap. **Новые** (`pending_count` / `pending_document_ids`) excludes `Documents.is_hidden`. **Последние** is `DocumentRecent` (per doctor, unique document, max 200, page 50). List title is topic then type (`" ".join(topic, type_doc)`). Topic is the value of the field whose `cda_option` is `CDA_TOPIC_ID_FOR_DOCUMENT_MANAGER` (`laboratory.settings` / `local_settings`, default `-1` disables). Lookup uses the document schema snapshot (`cdaOption` on fields), then live `ParaclinicInputField` + `ParaclinicResult` / `body_values`. `documents/recent` re-reads the current document topic; save and open also refresh stored `DocumentRecent.topic`. Schema dump now stores `cdaOption` on each field. Type list on this page calls `types/list` with `availableOnly`: empty `TypeDocumentCreator` set is visible to everyone; otherwise only listed doctors. `documents/create` uses `TypeDocuments.can_create`. Constructor `types/list` is unfiltered.

A filled read list limits reading to the creator, a superuser, listed readers, and listed writers. An empty write list lets only the creator and a superuser attach documents. A document has one `Documents.block`, the same way it has one case. Group **Создание блоков** (migration `0033_create_blocks_group`) or a superuser creates a block. - **DOU constructor** (`/ui/construct/dou`): groups, types, structure, **Шаблоны документов** (`is_layout_template` researches via `ParaclinicResearchEditor`, department `-17`), and **Показатели** (`Researches.is_indicator`, department `-18`, same editor and field rules, one field only). Layout templates are no longer created under `/ui/construct/descriptive` (**Шаблоны**). **Формы** stay on descriptive.
- **DOU registrar** (`/ui/document-registrar`): home button **ДОУ-Р** sits after **ДОУ-2** and uses the same access. The page is full width. Each `PlaceSection` stores optional `type_section`; the place editor picks it with a treeselect. Subsections come from constructor **Подраздел/место** (`PlaceSection`); items are `TypeDocuments` assigned to that place (unassigned types under **Общие**). An empty **Тип раздела** shows no tabs and no values. **Избранное** is a synthetic first option (`DocumentPickerFavorite`: current doctor plus a document type or case type). **В избранное**, next to **Создать**, toggles the selected picker item; that type is listed only for that doctor when **Избранное** is chosen. The open document form has a star before the title. `UserFavoriteDocument` and `UserFavoriteCase` store the doctor and the document with no cap. A document created from a case type creates `DocumentCase` (empty topic, automatic creator and `created_at`) and links it from `Documents.document_case` (empty for ordinary documents). The open form shows a **Дело** block above the document: only the topic is editable; creation date and creator are on one read-only line. A confirmed document shows **Подтверждено** with the confirmer, date, and time (`whoConfirmed`, same text as `/ui/results/descriptive`). Confirm is rejected while that topic is empty. Case access is `DocumentCaseAccess` (case + doctor). The creator and a superuser can change it at any time in the same addressee modal (**Доступ**). An empty list leaves the case documents visible only to the creator and superusers; listed doctors can open them too. Documents without a case stay on the previous rules. `Documents.type_case` still marks case favorites. Navbar links **Избранные документы** and **Избранные дела** on `/ui/document-manager` and `/ui/document-manager-2` open that card. There is no **Виды дел** tab. An empty treeselect lists every place and, when that mode is open, every document type except cases. A chosen type keeps **Общие** and shows only places of that type; the open list is document types of those places. Cases appear on the place tab they are assigned to. The picker loads `researches/all?dou=1` (places + types + cases). Value buttons default to **10 columns** (`defaultResearchColumns`); each `PlaceSection.columns_count` (constructor field **Колонки**, 1–12) overrides that for its tab. `/ui/directions` keeps the usual 4-column layout.
- **Research picker DOU**: virtual department `Podrazdeleniya.DOU` `10010` is always in `GET_ALL_DEPARTMENTS`. `/ui/directions` still hides type **ДОУ** unless `RESEARCH_PICKER_SHOW_DOU` is true (`research_picker_show_dou`). When it is shown, tabs and lists are the same as DOU-2 (section-type treeselect, `PlaceSection`, `TypeDocuments`). Case types (`TypeCases`) have no separate tab: each case is listed on its `PlaceSection` tab. A case without a place is omitted from the picker. The ordinary **Все** control on other service types stays. Document picker pks are `1_000_000_000 + TypeDocuments.pk` (`is_dou_document_type`); case-type pks are `2_000_000_000 + TypeCases.pk` (`is_dou_case_type`). Both are omitted from the direction basket and from create. Only one DOU item can be selected at a time (clicking another replaces it). Layout templates and indicators stay in the constructor (`-17` / `-18`) and are not listed in the DOU picker.
- **DOU document manager** (`/ui/document-manager`): `DOCUMENT_MANAGER_FOR_ALL` in `laboratory.settings` / `local_settings` (default `False`) is an on/off switch: when `True`, the menu button, page, and `ДОУ: просмотр документов` APIs ignore groups and are open to every authenticated user (`modules.document_manager_for_all` on the frontend). When `False`, access stays on group **ДОУ: просмотр документов**. `HIDE_DOCUMENT_MANAGER` (default `False`, override in `local_settings`) hides the **ДОУ** menu button and `/ui/document-manager` for everyone, including a direct URL (`modules.document_manager_enabled` is false). **ДОУ-2**, the constructor, and document APIs stay. Constructor, history, hide, and confirm-reset stay on their groups. A `Documents` row has `Issledovaniya.document`; field values are `ParaclinicResult` on that iss (same payload as `directions/paraclinic_result`, without direction-only side effects). Save stays on `document-manager/documents/save` because DOU users have group **ДОУ: просмотр документов**, not the doctor groups for `paraclinic_result`. Confirm writes `Issledovaniya.time_confirmation` and mirrors `Documents.time_confirm` / `who_confirm`. Confirm reset is limited to Django group **Сброс документов** (or superuser); details returns `canReset`. Hide is allowed for the document author until confirm, plus superuser and Django group **Скрытие документа**; details returns `canHide`. Hidden documents are listed/opened only for that group and superuser; the **Скрытые** checkbox is shown only then. **Мои дела** sits before it and lists non-hidden documents of cases the current user created or was granted access to. Opening a case from **Мои дела** or from **Избранные дела** shows only the case block and a **Документы** list. Each row is one line (topic, type, creation date, creator) plus a blue **Перейти** link that opens that document in a new tab via `?document=`. **+** / **−** beside the heading expand or collapse every row; the same control on a row shows or hides that document's electronic form. Other filters keep the document form and the case block without that list. The case heading is **Дело №** plus the case pk, with a star that toggles `UserFavoriteCase` for that case (`record-favorites/toggle` with `case: true`). Each document line starts with the document pk. A case has a comment and can be closed by its creator or a superadmin; closing stores the date and the user. Under the document buttons, a treeselect lists open cases the user can access and assigns the document to the chosen case. It stays off together with **Скрытые**, **Новые**, **Последние**, **Согласовать**, and **Подписать**. Actions write `slog.Log` with types 260000–260005 (`key` = document pk). History UI `/ui/document-history` (group **История документа**) matches `/ui/direction/history` (search by number, grouped event cards) and reads only those types via `document-manager/documents/history` — not `/ui/logs`. **Найти** looks up `Documents.pk` via `documents/find` (`Documents.find_by_id`); changing group reloads types only, not the document list. Field type 45 **Адресат** stores JSON `[{id, fio}]`; save syncs `DocumentReview.doctor_review` for the document. Addressee sets are `AddresseeGroup` / `AddresseeGroupMember`. Surrogate group **Все** is only for Django group **Все адресаты** or superuser (constructor may still search all employees). Constructor sets have empty `who_create`; personal sets from the document modal belong to the current doctor and are listed only for that user. Opening a confirmed document (`documents/details`) stamps `time_review` on that user's pending `DocumentReview` row without reloading `Issledovaniya`. `documents/details` prefetches `Issledovaniya`, loads `ParaclinicResult` without joining `ParaclinicInputField`/`input_templates`, reuses the latest type schema when `Documents.schema` is missing, and checks hide/reset groups in one query. Repeated opens update `DocumentRecent` without trimming the 200-row cap. **Новые** (`pending_count` / `pending_document_ids`) excludes `Documents.is_hidden`; list titles are `{id} {title}` (`Documents.title_with_id`, no `№`). **Последние** is `DocumentRecent` (per doctor, unique document, max 200, page 50; `get_page` keeps only `is_hidden=False` and `time_confirm` set; same `{id} {title}`). List title is topic then type (`" ".join(topic, type_doc)`). Topic is the value of the field whose `cda_option` is `CDA_TOPIC_ID_FOR_DOCUMENT_MANAGER` (`laboratory.settings` / `local_settings`, default `-1` disables). Lookup uses the document schema snapshot (`cdaOption` on fields), then live `ParaclinicInputField` + `ParaclinicResult` / `body_values`. `documents/recent` re-reads the current document topic; save and open also refresh stored `DocumentRecent.topic`. Schema dump now stores `cdaOption` on each field.

## Data Patterns

### Entity Relationships
```
Card (Patient)
  ↓ 1:N
Napravleniya (Referral)
  ↓ 1:N
Issledovaniya (Research)
  ↓ 1:N
Result (Result)
```

### Key Patterns
- **Soft Delete** - `hide`, `cancel` flags instead of physical deletion
- **Audit Trail** - `slog/` module, `create_at`, `who_create` fields
- **Multi-tenancy** - Support for multiple hospitals via `Hospitals`, data filtering by organization
- **Research internal_code:** empty `Researches.internal_code` is filled as `{pk}-code`. Command `fill_empty_internal_code` backfills existing rows. Constructor save (`researches_update` for `/ui/construct/descriptive`) fills the same way after save if the field is empty.

## Integration Patterns

- **Adapter Pattern** - RMIS adapter, HL7 adapter (hl7apy), ASTM adapter (lab equipment), SOAP adapter (zeep)
- **Queue Pattern** - Celery for async processing, queues for external system data sending
- **Webhook Pattern** - API endpoints for external system data reception
- **JSON order export daemon** (`daemons/ftp_push_json_orders_start.py` → `ftp_orders/json_export.py`): `api/requests/create` writes `{pk}_{YYYYMMDD}_{HHMMSSmmm}_ord.json`, `api/requests/link-image` (link branch only) writes `{pk}_{YYYYMMDD}_{HHMMSSmmm}_{studyInstanceUID}_dcm.json`. Payload holds every `Napravleniya` concrete field plus the `_l2_file_type` tag (`ord`/`dcm`). `ord` also adds `family`, `name`, `patronymic`, `birthday`, `sex`, `doctor_id`, `uuid` (`DoctorProfile.uuid` of the creating doctor), `hospital_oid`, `internal_code` (first research), active `documents` (`type`, `serial`, `number`) from related patient/hospital, and `files` (`name`, base64 `content`) from `NapravleniyaFiles` within `REQUEST_CREATION_FILES_MAX_TOTAL_MB` and `REQUEST_CREATION_FILE_EXTENSIONS`. Import writes those files onto the new request, or appends names that are not already stored when `id_in_hospital` exists. `api/requests/update` spools another `_ord.json` after new files are saved. The import log keeps file names only. `dcm` adds `uuid` (`Equipment.uuid`), `hospital_oid`, `study_instance_uid`, and `EquipmentReceive` patient/DICOM tag metadata. Views only spool atomically (`.tmp` + `os.replace`) to `FTP_JSON_ORDERS_SPOOL_DIR` (default `<BASE_DIR>/ftp_json_spool`); the daemon uploads to `FTP_JSON_ORDERS_URL` every `FTP_JSON_ORDERS_INTERVAL_SECONDS` and after a successful `STOR` moves the file to `FTP_JSON_ORDERS_ARCHIVE_DIR` (default `<BASE_DIR>/ftp_json_archive`). Empty URL disables upload; all settings live in `laboratory/settings.py`, overridable in `local_settings.py`.
- **JSON order import daemon** (`daemons/ftp_pull_json_orders_start.py` → `ftp_orders/json_import.py`): polls `FTP_JSON_ORDERS_PULL_URL` (must not equal the push URL). `_ord.json` / `_l2_file_type=ord` creates a request (`id_in_hospital` = source `id`, research by `internal_code`, doctor by `uuid` then `doctor_id`, patient by documents then FIO+DOB+sex); `_dcm.json` finds local `Equipment` by `uuid`, deletes any existing `EquipmentReceive` with the same `study_instance_uid` and equipment, creates a new one from payload metadata, and links it to the request. Successful files are deleted on FTP; failures stay for retry. Same functions are exposed as token APIs under `integration_framework/dicom/`: `json-order-create`, `json-study-link`, `json-order-get`. Import does not spool outgoing JSON.
- **JSON result export/import:** after a direction is fully confirmed, `Napravleniya.post_confirmation` synchronously spools `{id}_{YYYYMMDD}_{HHMMSSmmm}_res.json` when `hospital.json_result_auto_export` is true. `id` is `id_in_hospital` if set, otherwise the direction `pk`. Payload is `_l2_file_type=res`, `id`, `pdf` (base64), `time_confirmation`, `doctor_fio`. Spool/archive dirs are `FTP_JSON_RESULTS_SPOOL_DIR` / `FTP_JSON_RESULTS_ARCHIVE_DIR` (defaults `<BASE_DIR>/ftp_json_results_spool` and `ftp_json_results_archive`). Daemon `ftp_push_json_results_start` uploads to `FTP_JSON_RESULTS_URL`; `ftp_pull_json_results_start` and token API `json-result-create` apply the result to the original request (`pk=id`): PDF on `IssledovaniyaFiles`, `time_confirmation`, `doc_confirmation_string`.
- **REST result pull daemons** (`daemons/`): `rest_api_pull_result_start` runs once a day at `REST_API_PULL_RESULT_RUN_TIME` (`HH:MM`, `TIME_ZONE`); `rest_api_get_new_results_start` asks each hospital API `GET_NEW_RESULTS` then runs `_run_pull_for_orders`. Interval: `REST_API_GET_NEW_RESULTS_INTERVAL_SECONDS`. Per-hospital auth from `Hospitals.auth_data_for_rest`. REST keys are cached per hospital (`{hospital_id}_hosp_key_auth`), TTL `REST_API_HOSPITAL_KEY_TTL_MINUTES` (default `5 * 24 * 60`, overridable in `local_settings.py`).

## Document Generation Patterns

- **Template Method** - Base templates for document types
- **Builder** - Step-by-step complex document construction (PDF, DOCX via reportlab, python-docx)
- **Form Constructor** - Dynamic form creation via `construct/`, JSON-based configuration
- **Tube barcodes** (`/barcodes/tubes`): label size `BARCODE_SIZE` (`43x25`), left offset `tube_barcode_offset_x` (mm, default `TUBE_BARCODE_OFFSET_X` `-3`), long-number bar index `TUBE_BARCODE_WIDTH_MINDEX`. Overall Code128 width is `tube_barcode_width_mm` (mm; `0` keeps the digit-length formula). Override per request with `barcode_width`. Runtime values live in `appconf.Setting` and are edited under constructor **Штрих-коды ёмкостей** (`/ui/construct/tube-barcode`, group **Конструктор: Ёмкости для биоматериала**). `laboratory/settings.py` / `local_settings.py` are defaults until first save.
- **ISS attached files:** `appconf.Setting` `iss_keep_only_latest_file` (boolean, default off). When on, `IssledovaniyaFiles.keep_only_latest` after `directions/add-file` deletes older files for that iss and keeps the newest. Frontend (`FileAddModal`) still shows upload so a new file can replace the old one. `result_print` deduplicates `Issledovaniya.link_file` and `IssledovaniyaFiles` PDF paths so the same attachment is not printed twice.

## Security Patterns

- **RBAC (Role-Based Access Control)** - Django groups, roles (doctor, lab tech, registrar, admin)
- **Authentication** - Django Auth, 2FA (pyotp, QR codes), digital signatures for documents
- **Data Protection** - Sensitive data encryption, patient data protection, CORS for API

## Performance Patterns

- **Caching** - Redis, Memcached for sessions, DB-level caching
- **Eager Loading** - `select_related`, `prefetch_related`, `api/prefetch.py` for query optimization
- **Pagination** - For large lists, lazy loading for heavy data
- **DB Optimization** - Indexes (`db_index=True`), denormalization where needed, raw SQL for complex analytics

## UI/UX Patterns

- **Component-Based Architecture** - Reusable Vue.js components, isolated logic, props for data passing
- **State Management** - Vuex for global state, local component state
- **Progressive Enhancement** - Basic functionality without JS, enhanced with JS
- **TwoSidedLayout** - fixed left width (`leftWidthPx`); `resizable` adds a col-resize gutter, emits `update:left-width-px`, clamps min left/right. Other pages keep a static split unless they opt in.

## Testing Patterns

- **Test Organization** - Unit tests in `__spec__/` directory
- **Fixtures** - Django fixtures, factories for test objects

## Anti-patterns to Avoid

1. **God Objects** - Keep models focused
2. **Tight Coupling** - Modules should be independent
3. **Hard-coded Values** - Use appconf settings
4. **N+1 Queries** - Use prefetch/select_related
5. **Magic Numbers** - Use constants
